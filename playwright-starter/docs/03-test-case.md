# TC-001. Гість додає Audi TT до Garage

| Поле | Значення |
|---|---|
| ID | TC-001 |
| Модуль | Garage, гостьовий профіль |
| Тип | Функціональний, позитивний, E2E UI |
| Пріоритет | Високий |
| Автоматизація | `tests/guest-add-car.spec.ts` |
| Вимоги | R1–R9, R11, R37, R45, R51 (`docs/01-normalized-requirements.md`) |
| План | `specs/guest-add-car-plan.md` |
| Браузер | Chromium, Playwright 1.62.1 |

## Опис

Перевірити, що гість може додати автомобіль Audi TT із пробігом 12000 і побачити його у Garage.
Вхід через `Guest log in` є підготовкою, а головний результат — поява авто у Garage.

## Передумови

1. Стенд `https://qauto.forstudy.space` доступний.
2. Локальний `.playwright/cli.config.json` містить HTTP credentials стенда (не зберігається у Git).
3. Нова чиста сесія браузера: гостьових даних ще немає.
4. Виконано `npm ci` і `npx playwright install chromium`.

## Тестові дані

| Поле | Значення |
|---|---|
| Brand | `Audi` |
| Model | `TT` |
| Mileage | `12000` |

## Кроки та очікуваний результат

| № | Крок | Очікуваний результат |
|---|---|---|
| 1 | Відкрити головну сторінку | Видно кнопку `Guest log in` |
| 2 | Натиснути `Guest log in` | URL містить `/panel/garage`, видно заголовок `Garage` |
| 3 | Натиснути `Add car` | Відкрито pop-up `Add a car` |
| 4 | У `Brand` обрати `Audi` | У полі вибрано `Audi` |
| 5 | У `Model` обрати `TT` | У полі вибрано `TT` |
| 6 | У `Mileage` ввести `12000` | Поле містить `12000`, кнопка `Add` активна |
| 7 | Натиснути `Add` у pop-up | Pop-up закрито, URL містить `/panel/garage`, запис `Audi TT` видно у Garage |

**Автоматичні перевірки (дві, згідно зі `specs/add-car.md`):** URL містить `/panel/garage`;
запис `Audi TT` видимий. Решту результатів із таблиці тест не перевіряє окремо: ці кроки підтверджують
дії Playwright, а значення зафіксовані в огляді UI агентом planner.

## Постумови

- У поточній сесії в Garage є авто `Audi TT`.
- Очищення не потрібне: дані гостя існують лише в межах сесії браузера (R33), а Playwright створює
  новий контекст для кожного тесту. Сам тест цього не перевіряє.
- Записи в інших сесіях і дані зареєстрованих користувачів не змінюються.

## Критерії проходження

- **Passed:** усі кроки виконано, обидві автоматичні перевірки успішні.
- **Failed:** будь-який крок або перевірка не виконується. Падіння спершу діагностують
  (термінал → HTML-звіт → screenshot → trace), і лише потім класифікують.
- **Blocked:** стенд або налаштування недоступні. Фіксується blocker і рішення `STOP`.
